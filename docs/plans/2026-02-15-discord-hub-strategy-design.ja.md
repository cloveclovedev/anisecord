# anisecord 戦略デザイン: Discord Hub路線

## ポジショニング

anisecordは「Discordサーバーに住むAIアシスタント群」。日常のメモ・会話の中から、アウトプット生成・ライフログ分析・計画支援・ナレッジ蓄積を自然に行うプラットフォーム。

### 競合との差別化

- **Claude Code / ChatGPT**: 「AIに話しかけに行く」体験。エンジニア・技術者向け
- **Notion / Obsidian**: 「自分で整理する」体験。構造化が前提
- **anisecord**: 「生活空間にAIが居る」体験。入力のハードルが極限まで低い

### Discord Hubの優位性

| 観点 | Discord Hub | AI App+Plugin | 自前Web |
|------|------------|---------------|---------|
| 導入障壁 | 極低（サーバー招待のみ） | 中（アプリ+Plugin設定） | 高（新規登録） |
| スマホ画像入力 | 天然にシームレス | 可能だが多ステップ | 自前実装必要 |
| メモ/AI切り替え | チャンネル分けで実現 | 不可能（全部AI送信） | 自前実装必要 |
| コミュニティ効果 | あり | なし | 自前実装必要 |
| APIコスト制御 | ユーザー制御可 | 制御困難 | 自前実装必要 |
| ターゲット層 | 幅広い（Discord既存ユーザー） | 技術者寄り | 全層だが獲得困難 |
| 開発コスト | 低（既存資産活用） | 中（Plugin API学習） | 膨大 |

**コアバリュー**: 「意識せずに蓄積し、必要なときにAIが価値に変える」

## 4つの機能の柱

### 柱1: アウトプット生成
蓄積された会話・メモからSNS投稿、ブログ下書き等を生成。
- 既存: SNS-X
- 拡張候補: ブログ下書き、週次サマリー、議事録

### 柱2: ライフログ x AI
画像・テキストで日常を記録 → AIが分析・アドバイス。
- 既存: Nutrition
- 拡張候補: 運動記録、睡眠、支出管理

### 柱3: 計画・タスク管理（優先度高）
外部ツール（TickTick, GitHub Issues等）と連携し、計画を自動生成・投稿。
- today's plan / weekly planの日報チャンネル自動投稿
- 外部ツールからの情報集約がコア

### 柱4: ナレッジ蓄積
メモ・リンク・会話をAIが整理・検索可能にする。

### 柱の関係性

```
外部ツール ──→ [柱3: 計画]  ──→ 日報チャンネル
                    ↑
[柱4: ナレッジ] ←→ Discord蓄積 ←→ [柱2: ライフログ]
                    ↓
                [柱1: アウトプット] ──→ SNS/ブログ等
```

入力（計画）→ 蓄積（ナレッジ・ライフログ）→ 出力（アウトプット）という自然な流れ。

## サーバー/チャンネル設計

### A. パーソナルサーバー（1人1サーバー）

各ユーザーが自分のサーバーを立ててanisecord Botを招待する。チャンネル名の命名規則に従うことでBotが各チャンネルの役割を認識する。

```
[ユーザーの個人サーバー]
├── #daily-plan       ← 柱3: today's plan自動投稿
├── #weekly-plan      ← 柱3: weekly plan自動投稿
├── #memo             ← 柱4: 自由メモ（AI不介入）
├── #knowledge        ← 柱4: AI検索・要約対象
├── #meal             ← 柱2: 食事記録
├── #sns-draft        ← 柱1: SNS下書き生成
└── #bot-config       ← 設定
```

### B. 共有サーバー（anisecord公式運営）

他人に見せてよい内容だけを共有するコミュニティ。

```
[anisecord共有サーバー]
├── #meal-share       ← 食事記録を共有（モチベーション）
├── #workout-share    ← 運動記録を共有
├── #sns-draft-share  ← 下書きのフィードバック
└── #general          ← コミュニティ会話
```

## サブスクリプション

- **管理単位**: DiscordユーザーID
- ユーザーに紐づくので、どのサーバーにいても同じ権限
- 共有サーバーではBotがコマンド実行時にユーザーIDでサブスク状態を確認
- 無料枠を設けて導入障壁を下げる（例: 月N回まで無料）

## 技術方針

- **DB**: Neon (PostgreSQL) - データ永続化のみ。月額$0
- **User管理**: モック継続。将来DB化する際はRepositoryを差し替えるだけ
- **認証**: Discord標準のuser ID（追加基盤不要）
- **サブスク**: Phase 2で実装。それまではfeature_enabledデコレータで十分
- **設計原則**: Repository層でサービス交換可能に（既存DDDパターン踏襲）

## 実装優先順位

### Phase 1: 計画・タスク管理（柱3）
1. Neon接続 + 基本的なDB基盤（migration等）
2. TickTick / GitHub Issues 連携サービス
3. `/daily-plan` コマンド + 日報チャンネル自動投稿
4. `/weekly-plan` コマンド

### Phase 2: サブスク + User永続化
5. UserRepository DB化
6. Stripe + サブスクデコレータ

### Phase 3: ナレッジ蓄積（柱4）
7. メモチャンネル監視 + DB蓄積
8. AI検索・要約コマンド

### Phase 4: 共有サーバー + コミュニティ
9. 共有サーバー設計・運用開始
10. ライフログ共有機能
